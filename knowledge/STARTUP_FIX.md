# V017.1 startup repair, 2026-09-05

User screenshot: current V017.1 URL, loading overlay still at the initial data stage. This is directly confirmed by source at 7a22685f548844d35c21d85e626e9abfe43d19c4. The screenshot alone cannot identify the user's failing request, network route or browser log. A precise client-side cause remains unknown.

This patch changes only startup. The same compressed JSON and binary payloads are split into 18 transport fragments of at most 512 KiB, with three concurrent requests. Each fragment, each reassembled gzip and each decoded payload is independently hashed. There is no substitute model, alternate host, restored historical runtime or weather integration. Original gzip files remain for byte-preserving reconstruction and compatibility; new startup requests only fragments.

The loader reads byte progress, enforces a 12-second idle deadline on both headers and body, retries at most three attempts per fragment, caps a fragment at 90 seconds, and stops the batch on terminal failure. Cache storage is optional; only verified fragments can be reused. Corrupt cache bytes are rejected. Startup reports download, checks, decompression and scene construction separately. A classic-script supervisor can report module-import failures. A real reconnect button preserves verified fragments through cache. The overlay is removed only after the original scene, effects and a rendered frame are ready. Cache-key revision is 20260905-loader-r1.

Original source payload SHA-256 remains 7ba1b923844f5161911e9aa63b18191e0d08ff8de4b3750204aa544320bd34c2 (16,647,376 decoded bytes).
