# 原生蒸馏 R1：实际范围

用户在当前对话批准按既定路线推进，要求移除贴图资源、蒸馏动画，并向参数化几何继续。来源固定为 AIRCRAFT@b8b2a6c441fa9a9b7e0831f4217511b4968d266e。已接受 V017 与既有在线页保持。

本轮已经写出可重复构建的编译器、独立机械控制器和对照测试。编译器检查原载荷以及全部源数据块哈希，只允许位置、法线、索引和新的控制数据进入新载荷。18 个源图片块和源 UV 不再打包；索引在验证最大值后无损转为16位。顶点和法线不量化，不减面。

动画先按原求值方式提取全部1784节点的初始姿态。非持续运行通道的初始姿态继续保留，其后续曲线不进入生产。起落架和弹舱分别建立标量控制输入与有限域曲线绑定，四发保存原轴、基准姿态和转速积分。采样曲线仍来自原动画，不能将这层转换称为全部真实机械原理已复原。

本地编译结果约4.06 MB飞机主体压缩数据，对比8.917196 MB旧载荷减少约54.5%；最后数值以固定Node版本的实际CI报告为准。新增图像0、UV0，1044组几何数值逐项相等。本地514组状态共916976次节点对比，最大局部量差1.11e-16，世界矩阵元素差8.88e-16。旋转步进、暂停与复位通过。浏览器和连续运行状态以真实报告为准，未运行不写通过。

测试首先捕获了恒定但非单位四元数的问题：直接折叠这类曲线会与源slerp产生约1e-9差异。已保留这类旋转曲线，仅折叠安全的恒定平移/缩放，重新测试后达到上述误差。阈值没有放宽。

外部核对使用Khronos glTF 2.0官方动画插值约定：https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html 。实现为了保持现有网页行为，仍逐项对照已锁定Three.js求值结果，不通过规范推断某条历史机构就是正确的。

新生产包无GLB、PNG、JPEG或原图片嵌入块。现有实时环境反射、阴影和任务烟雾仍会生成渲染缓冲，必须披露，不声称显存内没有纹理对象。天气、云和雾继续不接入。
