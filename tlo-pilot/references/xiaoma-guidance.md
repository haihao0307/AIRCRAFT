## 2. 可以复用到什么程度

| API | 实际行为 | 不能据此宣称什么 |
|---|---|---|
| `encodeWsd(chunks, options)` | 编码有序块，返回Node Buffer；默认major/minor/flags为0/1/0 | 不验证TLO、业务字段或schema |
| `parseWsd(input, options)` | 返回头及全部有序块，包括未知块的原始Buffer；默认校验CRC并拒绝尾随字节 | 不判断版本是否受支持、必需块、依赖或语义 |
| `decodeJsonChunk(chunk)` | UTF-8解码后调用JSON.parse | 不识别块类型，不检查字段含义；不能用于任意二进制块 |
| `crc32(data)` | 计算载荷CRC32 | 不认证来源，不检查语义，不保护文件头、块类型和顺序 |

文件头16字节：WSD0四字节、major/minor各uint16、块数/flags各uint32。分块头12字节：四字符ASCII类型、uint32载荷长度、uint32载荷CRC；多字节整数为小端。没有内建随机访问索引、压缩、宽整数列式编码或规则执行器。

需要修正旧文档容易造成的理解：示例载荷采用UTF-8 JSON，但实际编码器**也接受Buffer/Uint8Array原始字节**；字符串按UTF-8编码，其他值才经JSON.stringify。公版包原文件可利用原始字节路径封装，文件目录、路径、哈希和语义之间的对应仍须由试存配置公开定义。

普通JSON路径不能无条件保住任意数值或对象：BigInt会失败，部分值会被遗漏或改变。宽整数与相位须保留明确类型和精确表示；既有原文件不应先解析再重新序列化后冒称原字节相同。

未知块回写须保留原始载荷与顺序，并传回原major/minor/flags。不要开启`allowTrailingBytes:true`后仍宣称整个原文件可恢复：当前解析器不会返回所接受的尾部。是否字节相等最终以实际对比为准。

源码依赖Node Buffer；目前找到的是容器模块，没有找到可直接认定为普通浏览器通用TLO阅读器的实现。浏览器适配、人读视图、AI语义视图和业务校验由Skin Mother在其授权实验中实现和验收。

## 4. 旧schema不宜硬套的地方

`wsd-v0.1.schema.json`的根要求`format/frame/time/spectra/dna/objects/relations/events`，并禁止额外根属性。`frame`要求`earthId`、64位相位和毫米单位；`objectInstance.created`及`relation.validFrom`必需，而`timeKey`要求`dayIndex/tickOfDay/timeScale`。

虽然`timeScale`有`UNCERTAIN`选项，但日期和tick仍是必填值，这不足以忠实表达“世界时间完全未知”。把公版封存日填进`created`而不区分数字资产与实机含义，会把档案行为错写成实物制造事件。填一个假的earthId或世界时间，也不是兼容适配。

此外，uint64字符串的正则只限制形状和位数，未完整限制到uint64上界；四元数数组不保证归一化，引用也未检验是否可解析。schema通过仍不代表数值和关系语义正确。当前编解码器本身没有调用这份schema。

建议Skin Mother为本次试存公开一个**独立、明确标为实验的语义配置**，列出与旧schema的差异、未知值和局部参考架规则，给出自己的校验范围。可继续使用WSD0容器，但不能宣布新配置已经符合旧逻辑schema，或把它宣称为全体系TLO定稿。暂不需要小妈另造一份声称生产可用的新schema。
