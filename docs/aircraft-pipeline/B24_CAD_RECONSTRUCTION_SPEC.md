# B-24 CAD 重建规范 v1

## 1. 目标

本规范定义 B-24 原始图纸、官方手册、档案扫描和修复测量如何转译成可审查的数字工程母版。所有重建结果都要保留来源链、变型适用性、标定方法和误差记录。

本规范服务于历史数字复原、涂装定位、可视化和零件研究。它不构成制造、维修、结构安全或适航批准数据。

## 2. 坐标与单位

### 原始坐标

图纸中出现的 Fuselage Station、Wing Station、Water Line、Buttock Line、基准面和坐标表按原文记录，不改变符号和单位。

### 项目规范坐标

工程母版采用以下项目坐标：

- `X`：沿机身纵向，正方向向后。
- `Y`：横向，正方向向右舷。
- `Z`：竖向，正方向向上。
- 长度母单位：英寸。
- 派生显示单位：毫米和米。
- 原点：在总体图与坐标资料完成审核后锁定，锁定前使用 `datum_status: provisional`。

项目坐标与现有 GLB 坐标之间必须保存显式 4×4 变换矩阵。不得通过目测旋转后丢失变换记录。

## 3. 来源和实体追溯

每个重建实体至少包含：

- `entity_id`
- `source_id`
- `document_number`
- `drawing_number`
- `sheet_id`
- `revision`
- `page_or_frame`
- `source_region`
- `aircraft_variants`
- `production_plant`
- `block_range`
- `units`
- `calibration_id`
- `confidence_grade`
- `created_by`
- `review_status`

一个实体可绑定多条来源。来源冲突必须保留，不得静默覆盖。

## 4. 扫描入库

原始文件放入外部资产桥，仓库只保存登记表、哈希、预览和可安全版本化的派生矢量。

入库步骤：

1. 保留原始文件名和目录结构。
2. 记录字节数、SHA-256、下载日期、来源页和权利状态。
3. 检查页数、缺页、重复页、裁边、旋转、透视、压缩和可读性。
4. 为每页生成固定分辨率 PNG 预览。
5. 记录原图到预览图的变换。
6. OCR 只用于检索辅助，标题栏和关键尺寸必须人工核对。
7. 任何去噪、拉伸、锐化、反相或拼接都生成派生资产，并记录父哈希。

## 5. 标定

扫描图的印刷比例、浏览器显示比例和文件像素比例均不能直接作为尺寸真值。

标定优先级：

1. 明确标注的尺寸和坐标表。
2. 同一张图上的多个站位或已知间距。
3. 经批准的总体尺寸。
4. 多张独立原厂图的共同控制点。
5. 官方手册中的结构尺寸。
6. 修复实测。
7. 三视图比例，仅作为临时标定。

每张图至少使用两个分离控制点。大幅图纸应采用多点或分区标定，记录残差、最大误差和局部变形。标题栏中的“DO NOT SCALE DRAWING”等注记必须进入元数据。

## 6. 几何重建顺序

### Stage A：总体布置

- 全长、翼展、全高
- 主翼和尾翼相对位置
- 起落架接地点
- 炮塔、舱门、窗和主要开口
- 站位、水线和中心线

### Stage B：外形理论面

- 机身关键剖面
- 机鼻、驾驶舱、机腹和尾段过渡
- 主翼翼型、翼站、扭转和上反角
- 垂尾、平尾和控制面
- 发动机短舱与整流罩

### Stage C：结构骨架

- 框、桁条和地板梁
- 翼梁、翼肋和加强件
- 尾翼结构
- 炮塔座、起落架舱和炸弹舱结构

### Stage D：蒙皮与开口

- 蒙皮面板
- 搭接方向
- 检修盖板
- 门、窗和舱盖
- 铆钉与紧固件语义

### Stage E：机构和零件

- 起落架
- 控制面铰链
- 炮塔与武器安装
- 炸弹舱门
- 发动机安装和整流罩
- 可拆卸外部附件

## 7. 对称规则

机体整体可以具有对称设计，具体结构、设备、开口、天线、武器、维修改装和历史涂装可能存在左右差异。

只有满足下列条件时，CAD 实体才可镜像：

1. 原厂图或零件目录明确给出左右通用件。
2. 左右零件号和装配关系经过核对。
3. 照片、修理手册或实物证据没有显示差异。
4. 镜像操作保留来源与审批记录。

历史涂装继续执行左右独立重建规则。

## 8. 变型和生产批次

每条图纸与 CAD 实体必须声明适用范围。至少区分：

- B-24D
- B-24G
- B-24H
- B-24J
- B-24L
- B-24M
- PB4Y-1
- British Liberator variants
- 工厂代码和生产批次

当前第一条主线为 B-24J-CO。B-24M 图纸可以进入来源库和比较层，未经兼容审批不得进入 J 型正式几何。

## 9. 文件格式

| 层级 | 推荐格式 | 规则 |
|---|---|---|
| 原始来源 | PDF、TIFF、JPEG | 不可变，保存哈希 |
| 页级预览 | PNG | 固定生成参数 |
| 标定数据 | JSON | 保存控制点、矩阵和残差 |
| 2D 矢量 | SVG、DXF | 每条曲线绑定来源 |
| 参数化 CAD | FCStd 或等效格式 | 保存特征树和单位 |
| 中性 CAD | STEP AP242 | 用于跨软件交换 |
| 网页预览 | glTF、GLB | 明确标记为派生预览 |
| 涂装数据 | JSON、SVG、纹理贴图 | 绑定批准表面和 LiveryUV |

DWG 可作为交换副本，开放可验证格式仍需同时保留。

## 10. 置信度

- `A_verified`：原厂图与至少一条独立官方来源一致。
- `B_supported`：单张原厂图或多条官方手册共同支持。
- `C_reconstructed`：根据档案扫描和受控推导恢复，存在记录完整的假设。
- `D_provisional`：依赖低等级图纸或照片，等待工程来源。
- `E_visual_only`：仅用于可视化，不进入工程母版。

置信度针对实体或尺寸，不能只给整架飞机一个总等级。

## 11. 质量门槛

### 来源 QA

- 图号、版本、日期和适用性可读。
- 原文件哈希已记录。
- 权利状态和使用范围已记录。
- 派生资产能够回溯到原件。

### 尺寸 QA

- 关键尺寸由两个以上控制点标定。
- 保存残差报告。
- 总体尺寸与独立官方来源交叉核对。
- 单位转换有自动测试。

### 几何 QA

- 关键剖面和站位逐项比较。
- 曲面连续性、翼型厚度和扭转经过检查。
- 左右差异有明确来源。
- 开口、铰链轴和接地点具有语义锚点。

### 变型 QA

- 每个零件或装配声明工厂、变型和批次。
- 替代件、后期改装和修订历史分别记录。
- B-24M 资料不得静默覆盖 B-24J 数据。

### 发布 QA

- STEP、DXF 与参数化源文件尺寸一致。
- GLB 预览与 CAD 母版自动比较。
- 涂装锚点与面板、窗、铆钉和站位一致。
- 发布清单包含所有来源、假设、已知缺口和哈希。
- 上游审查前保持 `engineeringMasterApproved: false`。

## 12. 与现有模型的关系

现有权威 `b-24_liberator.glb` 继续承担运行时和视觉基线。CAD 知识库可以生成几何差异报告、比例校核和后续替换提案。任何模型替换都需要单独任务、独立视觉验收和明确批准，本规范本身不授权替换。

## 13. 自动化辅助工具层

自动化工具只能加速提取、拟合和预览，不能改变证据等级。

### img2threejs

允许用于从参考图生成程序化 Three.js 代理模型、建立可动画层级、执行多视图轮廓检查和网页视觉评审。输出固定标记为 `E_visual_only`，不得直接导出正式 STEP 或零件尺寸。

### Ortho2CAD

允许在隔离研究环境中把已经标定的正投影图转换成 CadQuery 重建候选。输入必须包含明确视图、单位、控制尺寸和变型标签。输出需要经过投影重合、关键尺寸、剖面、体积、左右适用性和来源追溯检查。

### 共同门槛

1. 输入图纸先完成来源入库和哈希验证。
2. 任何自动补全的隐藏区域单独标记低置信度。
3. 自动生成曲线和实体必须保存工具版本、参数、提示、随机种子和父来源。
4. 生成结果不得覆盖人工校核的 A 级或 B 级数据。
5. 只有通过 CAD QA 和上游审批的实体才可升级到工程母版。
