# B24 V012 螺旋桨连接件与蒙皮来源审计

## 1. 本轮范围

本轮从冻结的 V010 干净整机基线继续。完整 B24 飞机保持主对象，噪波保持表面辅助工具。

当前只处理三件事：

1. 核对螺旋桨与发动机之间看起来脱开的连接区域。
2. 审计原始锁定 GLB 中的蒙皮、材质纹理、法线贴图和铆钉语义信息。
3. 把排气油烟、机油渗漏、脚印、铆钉积污和板缝积污整理为来源驱动的独立表面层。

跑道、发动机启动顺序、滑行、起飞、巡航、投弹、返航和降落系统完整保留。本轮不修改，也不演示这条动作系统。80 DAYS 历史涂装继续作为独立版本层，等待人工确认。

## 2. 螺旋桨连接区域的源级结论

锁定 GLB 为 `b-24_liberator.glb`，大小为 `23,085,972 bytes`，SHA256 为：

`541c3dcfb98ab590cdb1bc90d6ddcdfe80bce2a4b937f3bccefab0c7efe8be0d`

原始 GLB 中四套 `anim_prop0_still` 到 `anim_prop3_still` 结构一致。每套包含：

1. 22 个子树节点。
2. 5 个带网格节点。
3. 3 个各为 1,119 三角形的桨叶网格。
4. 1 个 792 三角形的静态轮毂网格。
5. 1 个 1,128 三角形的实体连接机构网格。
6. 每套合计 5,277 三角形。

因此，四个螺旋桨的连接机构在原始源文件中都存在，源文件没有出现单侧缺件。

V009 和 V010 运行时按三角形数量对螺旋桨成员分类。1,128 三角形成员被命名为 `still-disc`，随后被赋予 `alpha: 0`。该成员实际承担轮毂后部和发动机之间的实体连接机构。隐藏它会让某些视角出现明显空隙，形成零件丢失或螺旋桨脱离发动机的视觉结果。

## 3. V012 修复方式

`B24_V012_PROPELLER_INTERFACE_PATCH.js` 在 V010 运行时完成后接入，只修正 1,128 三角形成员的材质分类：

1. `still-disc` 改为 `propeller-hub-connector`。
2. 使用原始材质颜色、金属度和粗糙度。
3. 透明度恢复为 1。
4. 继续列入 Ridged Noise 保护组，损伤权重保持 0。
5. 不创建网格。
6. 不移动节点。
7. 不修改动画。
8. 不修改原始 GLB、V010 HTML、80 DAYS 涂装和飞行动作系统。

网页增加四个局部检查入口，只用于快速查看四套连接机构。

## 4. 蒙皮、铆钉与纹理审计方法

审计脚本会从仓库中的 12 个锁定二进制分块重建原始 GLB，并再次验证完整大小和 SHA256。随后直接读取 glTF JSON，检查：

1. `normalTexture`。
2. `baseColorTexture`。
3. `metallicRoughnessTexture`。
4. `occlusionTexture`。
5. `emissiveTexture`。
6. 节点、网格和材质名称中的 rivet、fastener、panel、seam、skin、exhaust、oil、soot 和 weather 语义。

若原始材料没有独立法线贴图槽，只能说明 glTF 材质合同没有提供专用法线贴图。铆钉细节仍可能烘焙在基础色、金属粗糙度或几何中，所以图像内容和几何表面还要分别检查。

若没有经过来源确认的铆钉、紧固件或板缝遮罩，生产线必须关闭对应层。随机散点和程序化假板缝不允许代替来源数据。

## 5. 来源驱动的表面层

表面系统拆成下列独立层：

1. 发动机排气油烟。由排气口锚点、排气方向、局部气流和发动机工况共同驱动。
2. 机油与液体渗漏。由检修点、重力方向、局部气流和表面资格遮罩共同驱动。
3. 机组脚印与走道磨损。由走道遮罩、登机方向和交通密度驱动。
4. 铆钉与紧固件积污。必须有铆钉或紧固件遮罩。
5. 板缝与检修盖积污。必须有板缝拓扑或来源遮罩。
6. 雨水冲刷与灰尘流痕。由重力、气流、排水路径和尘土暴露驱动。
7. 漆面褪色与粉化。由漆面体系、朝向暴露和服役时间驱动。
8. 边缘掉漆与露底金属。由可磨损漆面、服务边缘和接触频率驱动。

Value Noise、fBm 和 Ridged Multifractal 继续用于遮罩内部的细微变化、边缘破碎和密度变化。它们不能单独决定油烟、机油、脚印、铆钉或板缝的位置。

详细约束保存在：

`data/b24-native/surface-modules/B24_SOURCE_DRIVEN_WEATHERING_CONTRACT_V001.json`
