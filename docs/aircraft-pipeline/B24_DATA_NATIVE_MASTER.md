# B24 数据原生飞机母体

## 1. 定位

B24 项目的长期主资产是一套可读取、可修改、可编译、可继承的数据母体。几何、动作、表面、乘员、武器、载荷和历史实例都由结构化合同连接。浏览器根据母体实时生成可观察的飞机，CAD、GLB、FBX、STEP 和纹理图只在指定阶段承担参考、验证或临时输出职责。

母体的首个对象为 `B24J_CO_DATA_NATIVE_MASTER`。完成后，同一套系统可以通过替换 AircraftDNA、装配配方、几何参数和机型行为参数派生 B25 等后续机型。

## 2. 总控关系

ChatGPT 负责上游总设计与判断：

1. 资料选择与证据等级。
2. 飞机家族、机型、工厂和批次适用性。
3. 整机装配树与稳定部件编号。
4. 几何配方、接口、运动轴和控制逻辑。
5. 表面分区、历史锚点和可插拔模块合同。
6. 视觉验收、冲突判断、替换优先级和批准状态。

`img2threejs` 作为执行适配器，负责按照已经批准的分析结果生成程序化 Three.js 代理、组件层级、浏览器页面、截图和几何检查。它没有资料判定、机型判定和母体批准权。

## 3. 六个核心图谱

### 3.1 AircraftDNA

保存飞机身份、坐标系、单位、变型、工厂、批次、整机尺度、系统布局和实例继承关系。

### 3.2 AssemblyGraph

保存稳定 `component_id`、父子关系、装配接口、安装基准、局部坐标、运动轴、可拆卸关系和替换状态。

第一版薄整机骨架包含 31 个节点。它覆盖机身分段、机翼分段、平尾、双垂尾、动力、起落架、武器、载荷、乘员和外部系统。

### 3.3 GeometryRecipe

保存能够重新生成形状的数据：

1. 站位与剖面。
2. 轮廓曲线与放样规则。
3. 翼型、后掠、上反角、扭转和厚度分布。
4. 开口、面板、舱门和活动边界。
5. 重复结构、铆钉阵列和紧固件模式。
6. 局部曲面参数与接口连续性。

GeometryRecipe 由统一编译器执行。自由编写的局部 Three.js 代码只能作为实验，经过验证的参数必须回写数据配方。

### 3.4 BehaviorGraph

保存语义输入、状态机、机构顺序、约束和输出目标。第一版包含 13 个控制器种子，覆盖螺旋桨、起落架、舱门、炸弹舱、载荷释放、襟翼、副翼、升降舵、方向舵、炮塔方位与俯仰、整流罩襟片和乘员离机。

原 GLB 的动画通道用于提取时序、方向、枢轴候选和运动范围。公开控制接口使用语义名称，避免依赖原模型节点名。

### 3.5 SurfaceGraph

保存稳定语义表面与模块插槽。第一版含 62 个表面槽位，覆盖：

1. 六个机身分段的左右外表面。
2. 左右翼内外段、上下表面、襟翼和副翼。
3. 平尾与升降舵。
4. 双垂尾与方向舵的内外表面。
5. 四组发动机短舱与整流罩。
6. 炸弹舱门。
7. 炮塔整流区域。
8. 座舱框架和腰部炮位整流区。

外部生产的 UV、矢量涂装、板缝、铆钉和表面程序通过 `surface_id` 接入。

### 3.6 EvidenceGraph

保存来源文件、哈希、图号、页码、提取方法、变换过程、置信度和审批状态。来自 GLB 的信息统一标记为视觉参考或派生测量，原厂图纸与官方手册可以在审核后提升几何与适用性权重。

## 4. 参考 GLB 的角色

锁定文件：

```text
b-24_liberator.glb
bytes  23,085,972
sha256 541c3dcfb98ab590cdb1bc90d6ddcdfe80bce2a4b937f3bccefab0c7efe8be0d
```

它提供以下可蒸馏信息：

1. 1,784 个节点及父子关系。
2. 348 个网格与世界包围盒。
3. 325,358 个三角形的参考外形。
4. 30 个材质和 18 个嵌入图像的分配关系。
5. 1 段动画与 2,518 条动画通道。
6. 起落架、螺旋桨、舱门、舵面和其它机构的运动示例。
7. 部件位置、粗略尺寸和整机比例的比较基准。

GLB 二进制保存在 GitHub Release。数据母体和运行时编译器不依赖该二进制才能工作。

## 5. 蒸馏与替换

### 5.1 先保留参考价值

1. 动画时序、运动方向和相互顺序。
2. 节点层级与相对变换。
3. 网格包围盒与部件位置候选。
4. 整机轮廓和粗略比例。
5. 原材质和 UV 分区的定位信息。

### 5.2 提取后重建

1. 机身、机翼、尾翼和短舱外形。
2. 起落架和舵面机构。
3. 动画片段和节点驱动方式。
4. 材质和 UV。

### 5.3 优先替换

1. 炮塔和机炮。
2. 乘员、座椅与离机路径。
3. 炸弹架、载荷约束和释放关系。
4. 对外控制 API。

## 6. 运行时编译

编译器读取数据母体，并生成浏览器内存中的对象：

```text
AircraftDNA
  + AssemblyGraph
  + GeometryRecipe
  + BehaviorGraph
  + SurfaceGraph
  + aircraft instance
  -> Three.js runtime aircraft
```

运行时可以生成 BufferGeometry、材质、GPU 参数、临时 UV、碰撞体、LOD 和动画状态。任何运行时产物都能从母体重新生成。

## 7. B24 到 B25 的继承

可复用系统包括：

1. 坐标与单位合同。
2. AssemblyGraph 语法。
3. GeometryRecipe 语法与通用放样器。
4. BehaviorGraph 控制器和状态机。
5. Crew、Payload、Turret、LandingGear 和 Propulsion 系统接口。
6. SurfaceGraph 与历史实例机制。
7. EvidenceGraph 和 QA 门槛。

B25 需要新增或替换机型 DNA、装配节点、几何参数、具体机构尺寸、武器配置和历史实例数据。生产线本身继续使用。
