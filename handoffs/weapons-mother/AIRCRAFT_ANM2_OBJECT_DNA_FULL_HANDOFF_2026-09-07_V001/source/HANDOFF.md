## 4. 仍然有效的成果

### 4.1 Object DNA 架构

稳定 ID、分类路径、真值等级 `known / inferred / estimated / unknown`、语义、功能、证据、测量、形态、表面坐标、材质、生命周期、行为、历史和验收分层继续有效。

### 4.2 参考输入身份保护

浏览器只接受大小与 SHA-256 同时匹配的原件，读取 28 节点、13 网格、51 访问器。原件留在本地内存，不上传、不缓存、不写入生成规则。这个安全边界继续有效。

### 4.3 双对象审查原则

Reference Twin 与 Native Twin 在同一工作台常驻。两者共享机械基准、相机、光照和中性材质。参考体只读，生成体只读自身规则。A/B 对照必须随时可见。

### 4.4 程序化表面研究

材质应按原因分层，区分基材、表面处理、制造痕迹、维护、磨耗、污染、氧化和微观响应。噪声有语义、尺度、坐标、种子、范围与通道响应。螺丝、开口、轮廓和板层由几何表达，不能依靠高频着色掩盖。

### 4.5 固定交付格式

每个用户审阅版本生成一个自包含 HTML，完成实际参考载入与浏览器预检后，写入固定 GitHub commit，并用 raw.githack 直开链接交付。

## 5. 已经退回的内容

W08 的测量结论和当前几何均被退回。W08 只保留为失败历史。W06 的整枪外观在质感上有可研究部分，几何完整度和准确性不合格。W07 改善了审查方式，注册与测量仍不合格。详细原因见 `FAILURE_LEDGER.md` 和 `W08_REJECTION_2026-09-07.md`。

## 6. 重新启动时禁止做的事情

1. 禁止把 W06 生成枪整体复制进新线充当基线。
2. 禁止复用 W07 的总长度缩放加包围盒中心注册。
3. 禁止复用 W08 的每对象独立归一化 64 截面包络，作为形态正确性证明。
4. 禁止依靠整枪平均误差掩盖机匣局部大误差。
5. 禁止缺少语义部件时仍把对象标记为完成。
6. 禁止在没有真实参考载入预检的情况下发布用户工作台。
7. 禁止用 B17 安装关系补 B24 空缺。
8. 禁止恢复 S01、R01 或 Image2ThreeJS 旧链路。
9. 禁止用材质、泛光、透明叠合和强高光掩盖几何差异。
10. 禁止把自动测试成功解释成历史准确或视觉接受。

## 7. 第一阶段执行顺序

1. 读取原件与 Object DNA 记录。
2. 建立语义部件对应表。
3. 建立共享机械基准和注册变换。
4. 用固定正交视图审查两侧、俯视、后视、轴向和局部近景。
5. 重建机匣基准壳体。
6. 重建顶盖与侧板层次。
7. 重建后部外观组。
8. 重建枪管根部、前环和机匣过渡。
9. 重建护套和前端结束结构。
10. 分区域通过数值门槛与人工预检。
11. 之后才进入 Surface Coordinates、年代材质、B24 外接系统和状态驱动动画。

## 8. 完成条件

下一次可见候选至少要满足：

1. 参考体已实际载入并完成固定视角检查。
2. 第一语义区域肉眼明显接近参考。
3. 关键基准误差、轮廓误差、表面距离和部件完整率达到预设门槛。
4. 中性材质审查通过，PBR 关闭时形态仍成立。
5. 缺失项清单与页面显示一致。
6. 用户尚未批准时，`visualAcceptance=false`。
